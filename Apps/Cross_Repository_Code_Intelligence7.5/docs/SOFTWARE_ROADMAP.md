# Study Tracker Roadmap

This roadmap uses the same structure for every phase so the plan stays easy to read, compare, and update.

## Roadmap at a glance

| Phase | Window | Focus | Main deliverables | Exit criteria |
| --- | --- | --- | --- | --- |
| A | 2026-08-01 to 2026-08-18 | Literature, presentation, and note taking | Read the core sources, record page references, prepare a short spoken summary, and map the critique notes in `criticise/code-atlas-roadmap` | The key sources, proposal, and roadmap critique can be explained without notes |
| B | 2026-08-19 to 2026-10-29 | NLP / Transformer / LLM course work plus protected interruption handling | Turn each relevant session into a tested module, baseline, or isolated experiment, keep daily proposal-understanding work active, and complete Expose understanding + presentation by 2026-09-07 | The course outputs can be reused in the main project and the Expose can be presented clearly |
| C | 2026-09-10 to 2026-10-19 | Eye surgery, healing, and full recovery | No study work, no computer-work requirement, and no catch-up pressure | Recovery is protected and the schedule remains stable |
| D | 2026-10-30 to 2027-02-18 | Main project and bachelor thesis | Implement the main system, evaluate it, and write the thesis draft | The project can be demonstrated, measured, and documented |

## Phase A — Literature and presentation

- Window: 2026-08-01 to 2026-08-18
- Goal: understand the sources, the proposal, and the critique roadmap well enough to explain the problem, the method, and the contribution in plain language.
- Deliverables: reading notes, page references, a short oral explanation, the first version of the study map, and a linked pass through `criticise/code-atlas-roadmap`.
- Exit criteria: the core papers, the Expose, and the roadmap critique can be explained without checking the text line by line.

## Phase B — Course work and reusable modules

- Window: 2026-08-19 to 2026-10-29
- Goal: convert the course material into reusable modules, baselines, and small experiments that support the main project while keeping proposal understanding in the daily work loop.
- Deliverables: one module per relevant session, a clear test for each module, a short result note, recurring proposal-understanding checkpoints, and completed Expose understanding and presentation readiness no later than 2026-09-07.
- Exit criteria: each finished session has a working artifact and a visible link to the thesis work, and the Expose plus roadmap critique can be explained and presented end-to-end by 2026-09-07.

## Fixed checkpoint — Expose readiness

- Deadline: 2026-09-07
- Requirement: the ability to understand and present the full Expose must be completed by this date.
- Verification: a full dry-run presentation with clear problem, method, contribution, scope, and timeline.

## Phase C — Recovery period

- Window: 2026-09-10 to 2026-10-19
- Goal: protect healing time and remove the pressure to keep studying during recovery.
- Deliverables: none; this phase is intentionally a no-work phase.
- Exit criteria: recovery stays protected and no backlogged study work is created.

## Phase D — Main project and thesis

- Window: 2026-10-30 to 2027-02-18
- Goal: build the core Study Tracker / Cross-Repository Code Intelligence result and turn it into a thesis-ready narrative.
- Deliverables: implementation, evaluation, screenshots or exports, and the thesis draft.
- Exit criteria: the system can be shown, the results can be measured, and the thesis can be written from the same evidence.

## Working rule

Every phase should be described with the same four questions:

1. What is the time window?
2. What is the goal?
3. What is the concrete deliverable?
4. What proves that the phase is done?

That keeps the roadmap consistent even when the content of the phases changes.

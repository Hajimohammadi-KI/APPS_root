## Ordered folders

1. `00_Inbox` — temporary intake; classify it during the weekly review.
2. `01_Problem_Design_Science` — research problem, Design Science, scope.
3. `02_Requirements_Use_Cases` — actors, use cases, requirements, acceptance.
4. `03_Corpus_Code_Intelligence` — frozen repositories and code-intelligence work.
5. `04_Static_Analysis_Roslyn` — syntax, semantics, symbols, calls.
6. `05_Entity_Framework_Data_Access` — mapping, reads, writes, persistence.
7. `06_Evidence_Provenance` — EvidenceRecord, SourceLocation, status.
8. `07_Graph_Neo4j` — graph schema, import, traversal.
9. `08_Retrieval_RAG` — Flat/Graph retrieval, answer pipeline, refusal.
10. `09_ML_NLP_Live_Course` — ten dated sessions and the independent lab.
11. `10_Evaluation` — gold data, RQ1/RQ2, metrics, validity.
12. `11_Thesis_Writing` — draft, figures, reproducibility, submission.
13. `12_Notes_ADRs` — reading notes, decisions, questions, meeting notes.

## File movement rule

An item enters `00_Inbox`, receives one primary folder based on the decision it
supports, and is then removed from Inbox. Do not duplicate a paper into every
phase. Put cross-phase links in a note or the Cross app source catalog.

Each reading note uses the same name as its source plus `.notes.md` and records:
problem, method, dataset, metrics, evidence model, project decision, and
limitation.

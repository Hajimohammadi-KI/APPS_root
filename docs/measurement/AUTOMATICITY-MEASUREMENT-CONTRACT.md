# Automaticity measurement contract

Status: Gate G2 implementation contract, version 1.0.0 (2026-08-22).

This contract creates a measurable baseline without claiming that production
analytics, cohort effects, CEFR gains, or language automaticity have already
been proven. The implementation is local-first and disabled until the learner
explicitly opts in.

## Scope and grain

- Learning-domain events keep one row per event within a route attempt.
- An event ID is the unique event grain. Route, response, evidence, content,
  plan, app-version, and content-version identifiers remain separate.
- Learning outcomes and engagement metrics are separate classes. A return or
  streak signal is not evidence that language performance improved.
- The normal learner backup remains private and may contain response text. The
  optional measurement export is a different file with a stricter schema.

Canonical implementation:

- `shared/learning-core/src/measurement.ts`
- `shared/learning-core/schemas/measurement-contract.schema.json`
- `shared/learning-core/src/measurement.test.ts`

The two app-package copies are generated by
`shared/learning-core/sync-workspaces.mjs`; they are not independent sources of
truth.

## Consent and deletion

Consent records include the purpose, category list, policy version, granted
time, current status, and revoked time. The categories are:

1. identifier metadata;
2. learning outcomes;
3. engagement events;
4. human-rating provenance, only when a real human rating exists.

Revocation immediately prevents a new measurement export. Deletion removes
only the local measurement consent and baseline records. It does not delete
learning progress or the learner's separately created private backup.

## Retention and transfer

- Storage: local device only.
- Maximum declared retention: 365 days.
- Transfer: user-initiated JSON download only.
- Automatic upload or hidden collector: none.
- Production telemetry: unavailable; cohort statistics must be reported as
  `N/A — production telemetry unavailable`.

## Baseline gate

A baseline can be captured only when:

1. consent is currently granted; and
2. every declared intervention flag is still `false`.

The baseline stores counts, IDs, versions, language, and selected session
duration. It does not copy learner response text or audio. Once captured for a
participant, it is reused instead of being silently moved after an
intervention.

## Privacy-safe export

Allowed fields include random local participant IDs, event/evidence/response/
content/plan IDs, timestamps, language, versions, verification state, numeric
scores, boolean evidence gates, and human-rating provenance.

Prohibited analytics fields include learner input or corrected text, prompts,
transcripts, audio, email addresses, IP addresses, hardware or device
fingerprints, and free-form intentions. Export is stopped when the recursive
leakage check finds a prohibited field name.

## Metric definitions

Metric definitions are shipped without fabricated values. A value is computed
only after its denominator and required evidence exist.

| Metric | Class | Numerator | Denominator | Minimum sample | Extra gate |
| --- | --- | --- | --- | ---: | --- |
| `first_attempt_valid_rate` | learning outcome | verified mastery-eligible first attempts | eligible first attempts | 20 | none |
| `time_to_first_valid_speech` | learning outcome | elapsed milliseconds to first verified speech | sessions with verified speech | 20 | recorded speech evidence |
| `delayed_recall_rate` | learning outcome | verified delayed-recall attempts | due delayed-recall attempts | 20 | due-review event |
| `novel_transfer_rate` | learning outcome | verified novel-transfer attempts | eligible novel-transfer attempts | 20 | novel context evidence |
| `independent_repair_rate` | learning outcome | verified independent repairs | repair-required attempts | 20 | independent repair |
| `return_after_gap_rate` | engagement | participants returning after at least 48 hours | participants eligible to return | 30 | engagement only |
| `false_positive_rate` | learning outcome | system-positive outcomes rated incorrect by a human | human-rated system-positive outcomes | 50 | human labels required |

All timestamps and metric windows use UTC in the export contract. UI display
may localize time separately, but it must not alter the stored instant.

## Deterministic data-quality checks

Every export is checked for:

- completeness of required IDs, versions, and timestamps;
- uniqueness of event IDs;
- timestamp and score validity;
- schema-version consistency and baseline ordering;
- prohibited raw-field leakage;
- first-class missing or insufficient sample status.

An error produces `failed` and blocks the download. An empty outcome sample
produces `insufficient-data`; it is downloadable for inspection but is shown as
N/A, never as zero effectiveness or success.

## Verified automated evidence

The canonical core tests cover consent, revocation, deletion isolation,
baseline gating, safe projection, leakage, duplicate/time/version errors,
metric-class separation, human-label requirements, and insufficient samples.

The English and German Playwright settings tests cover the complete browser
journey: opt in, capture baseline, download and inspect the JSON, revoke, and
delete while preserving an unrelated learner-progress sentinel.

Hardware microphone behavior, external provider accuracy, production
retention enforcement, cohort statistics, causal impact, and human rating
reliability are not established by these tests and remain N/A until separately
verified.
